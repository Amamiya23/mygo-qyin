# 桌面音频 PR 说明草稿

以下标题和正文可用于提交 Lilt 项目的 Pull Request。若提交给 MyGo 框架本身，
应将 `vendor/github.com/egoist/mygo/audio` 的改动映射为上游 `audio` 目录，保留
API、平台策略和测试，将 Lilt 调用层配置作为使用示例。

## 标题

桌面输出跟随音源采样率，并提供可选的 200ms 硬件静音预热

## 正文

桌面音乐播放此前固定重采样到 48000 Hz；切换不同采样率的歌曲时，设备可能还处于
5 秒空闲保留期，未立即重开。设备切频或长暂停唤醒后立即输出音乐，也可能丢失开头。

本改动在每次播放、恢复及设备打开时按音源元数据选择输出率。采样率变化会结束旧
设备会话并重开，无需等待空闲超时。同采样率、1 倍速播放跳过插值；设备缓冲、
进度补偿与 5ms 音量渐变按实际输出率计算。

新增 `Player.SetPreRoll(bool)`，默认关闭。Lilt 主音乐流通过
`SetPrimary(true).SetPreRoll(true)` 显式启用：新歌、从头重播、切频重连及空闲关闭后
恢复时，先打开设备，再输出 200ms 全零静音；短暂停且设备未关闭时直接渐变恢复。
静音期间不消费音源帧，不增加播放进度。普通音效默认无额外 200ms 延迟。

构建约束仅对受支持的 Windows、macOS、Linux 桌面后端启用上述能力，并显式排除
Android 与 iOS。Web 和移动平台保持固定 48000 Hz、无硬件预热；Web 恢复单个
AudioContext 复用，不因切歌重建。

实现采用共享输出流：音乐触发的预热期间，其他声音也等待剩余静音帧。音效不会
重新触发或延长预热；关闭、暂停、停止最后一个请求者或禁用其预热会取消剩余静音。
本 PR 不实现设备独占模式，系统共享音频服务仍可能重采样；音量、声像、变速和
音量平衡也仍会影响采样值，因此不承诺端到端 Bit-Perfect。

## 验证

- Linux、Windows、macOS 应用构建。
- 完整项目测试、音频回归测试、音频竞态检查和 `mygo vet`。
- 44.1/48/88.2/96/192 kHz、精确预热帧数、预热跨缓冲区边界、首帧与进度保留。
- 40ms/250ms 延迟补偿、短暂停恢复、5 秒空闲关闭后的恢复、打开设备过程中切歌。
- 普通音效默认不预热、冷启动不预热、加入音乐不重置预热、取消请求后不残留静音。
- 通过 Linux 386 目标实际运行非桌面策略测试，并编译 Web 音频测试。
- 通过各目标的 `go list` 检查 Web、Android、iOS 使用禁用桌面功能的策略文件。

验证不包含移动应用完整构建、浏览器实际运行或真实 DAC 的切频锁定测量。
完整行为、默认值与命令见 [桌面音频输出说明](desktop-audio.md)。
