# PR 标题

修复桌面端手动跨采样率切歌的旧曲残留，并平滑关闭旧输出

# PR 正文

## 问题

0.4.1 在使用 USB DAC 手动切换不同采样率的歌曲时，可能短促地听到上一首的音频片段，听感类似爆音。
用户补充测试中，48kHz 歌曲自然播放结束后切换到 44.1kHz 未出现同样现象。

调用层切歌时先 `Pause()` 旧播放器，再延迟 100ms `Close()`，以便完成原有 5ms 淡出。
如果下一首在此期间触发输出切频，已暂停的旧 voice 仍可能留在活跃混音列表中，
其淡出会在新输出会话的预热结束后继续，混入上一首的片段。
预热按输出帧推进，且后端存在提前缓冲，因此不能依赖关闭定时器保证旧 voice 已经退出。

## 修改

- 新输出会话建立时，移除已暂停声音遗留的淡出并清零增益状态，防止旧曲片段进入新输出；
  不 seek 或额外读取其音源，未关闭的播放器仍可正常恢复并淡入，仍在播放的声音保留。
- 手动切频前，将最后成功提交的立体声电平按**旧输出采样率**生成约 5ms 的线性归零包络，
  等待已排队输出和这段收尾播放完，再关闭旧会话。收尾不继续读取旧歌，也不消费下一首采样。
- 收尾按后端缓冲容量分块写入，覆盖高采样率下 AudioQueue 单缓冲容量为 512 帧的情况。
- 已确认自然排空的前曲不再追加人工收尾；同一会话自然续播同采样率歌曲后，之后的手动切频仍可正常收尾。
- 同步桌面音频文档、验证记录及 MyGo v0.8.3 本地补丁，支持重新生成 vendor 后恢复修复。

## 行为与取舍

**手动跨采样率切歌会比立即关闭多等待旧输出队列和约 5ms 收尾。**
通常与配置的 40ms/250ms 提前量相关，实际等待取决于系统服务和设备，并非严格的时间上限。
该等待不持有音频状态锁，不等待整首旧歌的自然 EOF，也不触发旧曲的自然结束通知。
这是为减轻生硬截断而对原先“主动切频立即关闭”策略作出的调整。

自然结束仍按已合并的评审修复等待尾音排空；同采样率且后端持续运行时保留原有淡出，
不增加预热。设备冷开或重开继续遵循 `SetPreRoll`，启用时才输出 200ms 静音。
ALSA 转换回退和停止后端重开策略保留。尚未输出过音乐的静音会话及没有排空接口的回退不增加收尾等待。
功能仍受桌面平台构建策略限制，Web 和 Mobile 行为保持原样。

## 验证

- 音频包完整回归 `-count=5`、音频竞态检查 `-race -count=3`、完整项目测试及 MyGo vet 通过。
- 新增回归覆盖 48→44.1、44.1→48、88.2→96、96→44.1kHz，40ms/250ms 延迟和预热开启/关闭；
  区分新旧声道，检查新输出无旧曲残留、精确首帧和源游标保留，以及旧输出归零包络。
- 回归覆盖同采样率淡出、自然结束后再次手动切频、取消待自然结束，以及 44.1/48/88.2/96/192/384kHz 收尾分块。
  高采样率分块属于假设备验证。
- Linux amd64、Windows amd64、macOS amd64 应用构建，以及 macOS arm64 / Web 音频测试编译通过。
- 更新后的桌面音频补丁重应用后，21 个文件与 vendor 一致；Linux 安装包校验通过。

在 Linux / PipeWire 与本机 USB DAC 上，用户试听确认前曲残留修复有效；
进一步使用平滑版后反馈切换体验明显改善。试听没有逐项记录所有歌曲、采样率组合与次数，
不能据此宣称所有切换爆音完全消除。Windows、macOS 和直连 ALSA 尚未完成本次修复的音乐听测，
跨平台编译和自动化测试不替代真实设备验证。
