# PR 标题

退出时增加 100ms 音乐淡出，并主动关闭桌面音频会话

# PR 正文

## 问题与效果

播放音乐时从托盘菜单退出，或将“关闭主窗口时”设为“退出应用”后关闭窗口，
原有退出流程会保存设置与播放位置，但没有显式完成音频收尾和输出会话关闭，听感可能是音乐突然截断。

本修改为正常退出增加 **100ms 的连续音乐淡出**：按当前输出采样率继续渲染当前歌曲，
逐帧降低音量至零，排空已排队音频后主动关闭设备会话，再结束进程。
淡出使用真实音乐采样，不是延长最后一个采样值，也不是单纯 Sleep。

## 实现

- 新增终止性的桌面音频 API `audio.Shutdown(context.Context) error`，拒绝后续 Play，
  并让并发调用等待同一次清理完成。音源保留至淡出结束或输出失败后关闭，
  避免提前关闭解码器；淡出期间保留声音的活跃生命周期，防止垃圾回收清理提前关闭音源。
- 音频写入、排空及设备关闭仍由输出线程执行，原生调用期间不持有播放器状态锁。
  淡出只使用已经在当前会话渲染的声音；退出恰逢切频时，不会误读下一首，
  混音步进与音量渐变也按旧设备实际输出率计算。
- 在 `App.OnQuit` 统一接入清理。设置和播放位置先保存，事件循环停止后等待音频收尾，
  不在可以取消的退出前置事件里提前关闭音频。淡出结束不会触发 OnEnd 或自动续播。
- 应用最多等待音频清理 **1 秒**，失败或超时记入日志后继续退出。
  上下文取消只结束等待，不跨线程强行释放仍被原生调用使用的句柄。
- 同步使用说明、验证记录及 MyGo v0.8.3 桌面音频补丁，重新生成 vendor 后仍可恢复本修改。

## 退出设置与兼容行为

| 操作或状态 | 行为 |
| --- | --- |
| 托盘菜单“退出” | 执行音频收尾并退出 |
| 设置为“退出应用”后关闭主窗口 | 执行相同的收尾流程 |
| 设置为“隐藏到托盘”后关闭主窗口 | 仅隐藏，继续播放 |
| 没有可恢复窗口的托盘或 Dock | 保留原有真正退出的回退行为 |
| 设备未打开，或暂停后缓冲已静音 | 直接完成清理，不额外播放 100ms 音频 |
| 仍在预热且尚未输出音乐 | 直接关闭，不开始读取歌曲 |
| 暂停但仍有声音排队 | 短防点击收尾，不恢复歌曲播放 |

退出时不重开设备、不等待 5 秒空闲超时，也不新增 200ms 预热。
100ms 退出淡出独立于设置中的“播放操作淡入淡出”；跨采样率切歌仍使用原有 5ms 收尾，
自然结束的尾音排空与设备重开策略保留。Web、Mobile 和其他不受支持的后端中，Shutdown 为无操作。

100ms 是淡出音频的长度，完整退出等待还可能包含 40ms/250ms 提前缓冲及设备处理时间。
强制杀进程、崩溃、音源数据不足、原生输出失败或清理超时，不保证完成平滑退出。

## 验证

- 音频完整回归连续 5 次、音频 race 检查连续 3 次、完整项目测试及 MyGo vet 通过。
- 用持续变化且左右声道不同的音源逐帧检查 100ms 淡出，覆盖 44.1/48/88.2/96/192/384kHz、
  40ms/250ms 提前量，确认连续音乐采样、精确包络和零终点；高采样率用例为假设备验证。
- 覆盖设备未打开、打开中退出、预热中退出、暂停且已经静音、切频中退出、短音源提前结束、
  不触发自动续播、不重开设备、取消等待及并发等待；原生 close 返回前不得提前通知清理完成。
- 应用测试通过真实设置控件选择“退出应用”，验证隐藏与退出的分支，以及无托盘回退和退出中窗口关闭不会递归 Quit。
- Linux amd64、Windows amd64、macOS amd64 应用构建，macOS arm64/Web 音频测试编译通过；
  Linux 386 运行测试验证非桌面 Shutdown 无操作。
- 桌面音频补丁重新应用后的 23 个文件与 vendor 一致，Linux 安装包及校验检查通过。

## 实机试听与边界

本机 AlmaLinux 10.2 x86-64、PipeWire 1.4.11 的 PulseAudio 兼容服务与 JCALLY USB DAC 上，
用户安装 100ms 版后反馈退出听感有所改善，并选定《ライアーコンプレッション》— 小玉ひかり作为固定试听曲目。

尚未记录该音源的具体采样率、退出时间点及完整重复次数，也未进行模拟或数字回采。
当前只能确认本机主观听感改善，不能表述为彻底消除所有截断或爆音。
Windows、macOS、直连 ALSA 及其他 USB DAC 的本次退出音乐听测仍待补充；
跨平台构建与自动化检查不替代这些实机验证。
